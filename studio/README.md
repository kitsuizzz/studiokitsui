# studio — the Chat half (chat.kitsui / AI Studio), vendored

This directory is AI Studio, brought into Studio Kitsui so the one app has
both halves: **Studio** (the canvas, at `/studio`) and **Chat** (this, at
`/chat`). One page serves both: `/chat` is the same shell as `/studio` (the
same top bar and left menu, one session list), and the SPA here renders only
the chat main, embedded in that shell (see **The landing**). The sources here
are the upstream project's, with the patches the
merge needs: the account work in `backend/app/accounts.py` (the HttpOnly
session cookie, session TTL, `/auth/config`, the `canvas` store kind), and the
logo lockup (`frontend/src/components/BrandLockup.tsx`, generated by
`brand/`).

## The landing

This half is the app's landing page for guests: the welcome's choice step
offers **Continue as guest** and **Create an account**, and the canvas half's
door (`/`) sends every guest here. The welcome carries no provider form — with
no model configured, **Continue as guest** still opens the chat: a warning
dialog names the missing model (and points to **Settings**, the provider box),
and a send that goes ahead anyway bounces back in the wall with the same note,
in red. An account skips the welcome —
its `place` record (the one unsealed record in its store, written by whichever
half is opened) routes the arrival to the half it left off in. The canvas
half's **Chat →** door is the welcome's one exception: it is a live crossing
(the shell stays; only the main area swaps) and it names the conversation when
the canvas has one, and that outranks the holds — a guest's own conversation,
or a signed-in account's (even one still on its no-model setup screen), opens
in the thread it names; a crossing with no conversation to open (or with one
this store no longer has) opens a session instead — the account's last
conversation, or a fresh one, never the welcome. A direct `/chat` load keeps
the old arrival rules (`?conversation=`; `door=studio` for one-shot crossings;
the welcome as a cold-start home). The lock is the one thing the door does not
outrank — while the store is locked the unlock screen shows, and the door
re-runs once the key is back. The halves carry no switch in a top bar: the
doors are what move between them, and the address follows (`/chat`,
`/studio`). The one place a conversation reaches the canvas is its own
**Studio** door (see **What runs**).

## What runs

| piece | where | how |
|---|---|---|
| the SPA | `frontend/` (React + Vite) | built to `frontend/dist`; the one shell page at `/chat` mounts its entry from `.vite/manifest.json` in the chat main (embedded: no chrome of its own) |
| the gateway | `backend/` (FastAPI) | accounts `/auth`, the end-to-end encrypted store, and the OpenAI-compatible `/v1` — run **inside nnstudio's own process** by `nn_gateway.py` (an ASGI bridge), answered at `/chat/auth/*` and `/chat/v1/*` |
| accounts DB | MariaDB (`backend/app/accounts.py`) | the upstream `docker-compose.yml` runs it (with searxng + a mock provider) |

The repository's `.env` carries the gateway's settings — `DB_*`,
`UPSTREAM_*`, `GATEWAY_MODELS`, `REQUIRE_SESSION`, `TURNSTILE_*`,
`SESSION_TTL_DAYS`, `COOKIE_SECURE`, `SEARXNG_URL`. Start from `.env.example`;
the root README's **Settings** documents them. `NNSTUDIO_STUDIO_WEB` moves the
SPA directory if needed.

The gateway can still run standalone for the upstream deployment
(`uv run uvicorn app.main:app` in `backend/`, its own `.env`) — it is the same
code, and `/v1` is then open unless `GATEWAY_TOKEN` or `REQUIRE_SESSION` says
otherwise.

The session seam — the one place the two halves touch. One session is a
conversation and the canvas it is bound to, and the binding lives in the
encrypted store: this half is its only writer, the canvas half owns the
design. A session's **Studio** door, on first click, mints a canvas id (`c_`
+ eight random bytes), seals a fresh blank canvas under the row key
`canvas|<id>` — a row's key is the AAD the record is sealed under — appends
the canvas's tab to the shared open-tabs record `session|current`, and then
crosses to `/studio?canvas=<id>`, the sync kept alive and capped so a slow
network never holds the door shut. The canvas half seals its rows, and this
half reads them back: the record's `session` field is what the boot heal
re-links a session with when its canvas is missing, and the agent's
**read_canvas** tool answers from that read — read-only, no consent, the
sealed record re-opened on every call. A guest's door crosses to a plain
`/studio`: no key, no binding.

## Build the SPA

    cd studio/frontend
    npm install
    VITE_BASE_PATH=chat npm run build      # assets under /chat/assets/…

`VITE_BASE_PATH=chat` is what makes the app address itself (and its gateway)
under the `/chat` prefix; the same-origin gateway default is `/chat/v1`, so no
other variable is needed. A build without it **fails on purpose** — the mount
is part of the build (a bare one used to emit `/assets/…`, which 404s under
`/chat` and serves a blank page), and the live gate fetches the manifest's
entry and stylesheet. The build also emits `.vite/manifest.json`, which the
one shell page reads at boot; the vite config's postcss pass scopes the app's
stylesheet to `#nn-chat` (and its theme attribute lives there too), so its
generic rules never touch the shell around it. nnstudio's server serves that
one page at `/chat` and redirects the built `index.html` there; the standalone
page remains the docker/nginx build. The Turnstile site key is read at runtime from `GET /chat/auth/config`:
there is **one key for the bot check** (the app's `.env`, `TURNSTILE_SITE_KEY`)
and no build-time key, so one build serves any deployment — and a deployment
that leaves `TURNSTILE_SITE_KEY` empty shows no widget at all (sign-ups then
fail the robot check).

## The database

Accounts, sessions and the encrypted store live in MariaDB — the upstream
compose stack publishes it on `127.0.0.1:3306` (`docker compose up -d
mariadb` in the AI Studio checkout). The gateway's own suite uses the
`aistudio_test` database the compose init script creates, and never the
development one:

    cd studio/backend && ../../.venv/bin/python -m pytest -q

## Tests

The upstream suites live in `backend/tests` (they need MariaDB; the upstream
Playwright `shot-*.mjs` gates stay under `frontend/tmp`). Studio Kitsui's own
suite covers the merge, the account work, and the seam between the halves:
the in-process bridge (`tests/gateway_bridge_test.py`), the Studio half's
account crypto pinned to this half's derivation — key shape, credential, the
HKDF record key against Node's own, the AAD binding, and the normalizer over
the page's legacy rows (`tests/studio_crypto_test.js`) — the seam read from
this half's side, the canvas half's sealer writing the rows this half's
`canvasLink` reads back (`tests/canvas_link_test.js`), and the live gates in
`tests/run.sh --live`.

## The brand

The Chat half's logo, favicon and top-bar lockup are generated from the app's
logo kit in `brand/`. After a change to the mark, run
`.venv/bin/python brand/tools/make_brand.py`, then rebuild this app
(`VITE_BASE_PATH=chat npm run build`). See [brand/README.md](../brand/README.md).
